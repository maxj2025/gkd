# 清屏设计方案

## 目标与设备边界

目标设备为小米 13，未 Root，具体 MIUI／HyperOS 和 Android 版本尚未确认。基于 GKD 二次开发安卓应用“清屏”，实现开屏广告跳过、已适配广告跳转页面的退出、按应用统计、低打扰运行和尽量降低耗电。

普通应用无法保证在系统强行停止、无障碍权限被撤销、厂商进程清理或后台策略限制之后仍持续生效。隐藏最近任务卡片仅影响界面展示，不会让进程免于清理。系统应用列表、无障碍列表和耗电记录仍然存在。

## 实现方式比较

| 方式 | 收益 | 代价与边界 |
| --- | --- | --- |
| 基于 GKD 的无障碍方案（推荐） | 复用规则匹配、点击执行和统计能力；普通设备可用；不必默认运行常驻通知服务 | 无法保证厂商清理后存活；广告可能短暂出现；依赖界面适配 |
| GKD 加可选 Shizuku 增强 | 可增加前台应用识别和部分系统操作能力 | 需要额外授权和服务启动；不能保证强行停止后工作，也不是通用隐身方案 |
| Root／系统级方案 | 可获得更强的系统控制能力 | 当前设备未 Root，不作为本项目实现前提 |

推荐第一种方案，Shizuku 不作为基础功能的必要条件。网络过滤无法单独可靠解决同域广告、界面跳过与跳转识别，因此不作为主要实现方式。

## 功能与验收口径

| 功能 | 实现约定 | 验收标准 |
| --- | --- | --- |
| 应用身份 | 名称“清屏”，独立应用 ID 和签名；保留上游开源许可证与必要署名 | 可与官方 GKD 区分安装，不覆盖官方应用 |
| 开屏广告 | 仅启用开屏广告类别；支持导入和手动更新可信规则 | 对明确适配的测试页面执行跳过；不宣称全应用覆盖 |
| 误触跳转 | 对明确适配的广告落地页执行返回或关闭；按应用独立开关，默认关闭 | 只在指定应用、页面与规则条件同时成立时触发；正常外链不应被全局拦截 |
| 应用统计 | 本地累计成功执行的跳过／返回动作，按应用展示次数及最近时间 | 失败动作不计成功；去重测试通过；界面标明“成功执行次数”，不等同于证明广告已消失 |
| 低打扰 | 默认关闭状态常驻通知服务、悬浮状态和调试服务 | 不主动发布常驻状态通知；保留系统可能显示的无障碍提示 |
| 最近任务 | 默认排除最近任务卡片，桌面入口保留 | 返回桌面后卡片不显示，仍可从桌面进入设置与统计 |
| 清理后台 | 借助已授权无障碍服务、允许自启动、后台省电不限制等系统设置尽量保活 | 区分划掉卡片、一键清理、系统杀进程、强行停止，分别记录小米实测结果 |
| 重启恢复 | 已授权无障碍服务由系统恢复绑定；检查开机接收器是否只启动必要能力 | 重启并首次解锁后实测；不能绕过首次手动授权或用户强行停止 |
| 停用 | 应用内提供暂停和跳转系统撤销授权入口 | 用户可以随时停止自动操作 |

## 权限

- 无障碍：基础必需；用于获取目标应用界面节点、执行点击和必要的返回操作，由用户在系统设置明确开启。
- 网络：仅在用户导入、更新订阅或检查更新时使用；统计保存在本地。
- 开机广播：辅助处理系统启动事件，不能突破强行停止限制，也不能替代无障碍授权。
- 自启动与电池后台策略：由用户在小米系统设置中允许；具体入口随系统版本变化。
- 通知：基础低打扰模式不主动申请常驻通知所需授权；若以后用户主动启用通知保活模式，必须明确显示其取舍。
- 悬浮窗、截图、使用情况访问、Shizuku、Root：基础方案不作为必需权限；关闭不需要的能力，不为保活额外申请。

## 耗电控制

1. 复用 GKD 事件与规则链路，先检查现有节流和匹配窗口，避免另建周期扫描循环。
2. 仅保留开屏规则与用户明确启用的应用规则，避免重复订阅与全类别匹配。
3. 在适配的开屏匹配窗口结束后停止该轮额外匹配；窗口长度须结合现有规则语义和测试确定，避免截断延迟出现的跳过按钮。
4. 熄屏时不进行无意义页面遍历；不使用常驻唤醒锁、定时拉活、静音音频或双进程互拉。
5. 不默认启动截图、HTTP 调试、悬浮窗、事件跟踪与高频日志功能。
6. 统计优先复用上游记录存储，核实成功动作记账时机与批量写入；不因界面刷新重复查询全部规则。
7. 电量改善以同机、同系统、同订阅、同操作脚本的对照测量为准；不预先承诺具体耗电百分比。

## 源码复用范围

已只读核对 GKD 主分支：存在按应用聚合的 TriggerStats、动作记录和规则设置；SettingsStore 已有 excludeFromRecents、enableStatusService、enableStatusOverlay 等选项；BootReceiver 当前调用 StatusService.autoStart。实施时固定基线提交，复核以上链路后最小修改。

按应用统计不能简单把所有自动动作称为“广告拦截”：须区分开屏跳过与广告页面退出，并核对动作成功、重复事件和记录持久化行为。

二次开发沿用适用的上游代码结构和许可证。首版不重写通用选择器，不复制第二套规则引擎，不默认加载未知远程规则。

## 界面

- 首页：运行状态、无障碍授权状态、暂停／启用、累计成功执行次数，以及仅在存在问题时显示的具体原因。
- 应用列表：应用名称、开屏跳过开关、广告跳转退出开关、累计次数与最近执行时间。
- 统计：按应用汇总，并区分跳过动作与退出动作。
- 设置：规则导入与更新、最近任务隐藏开关、后台设置入口、暂停服务与开源信息。

## 验证与交付

先验证规则筛选、成功动作计数与去重、旧数据兼容和设置持久化；再完成安卓编译与静态检查。具备模拟器时验证界面、授权入口、卡片隐藏和服务生命周期。最终交付 APK、对应源代码及简明配置说明。

小米 13 的真实耗电、一键清理后可用性、重启恢复与特定商业 App 的适配必须真机验证。当前未检测到 ADB 连接设备，不能将主机测试、源码检查或模拟器结果当作小米实测通过。
